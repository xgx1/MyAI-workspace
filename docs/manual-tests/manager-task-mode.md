# 管理模式任务清单 — 人工测试

被测实例：**3081**（`~/.dsh-dev`，`dsh-web-dev.service`）。生产 3080 未部署本轮改动。

## 环境准备

- `systemctl --user restart dsh-web-dev.service`（改了 host 侧代码后必须重启，客户端改动刷新即可）。
- 打开 3081，用启动日志里那条带 token 的地址。
- 任务清单入口：侧边栏「任务管理」。

## 用例

### 启用与管理模式

- 新建会话后点会话头的预设名（默认「JS 项目」），列出「管理模式」。
- 选中后：会话头的预设显示「管理模式」；工具目录里没有命令行、文件读写、浏览器等执行工具。
- 在该会话里发一句要干活的话：它不会自己动手，而是创建另一个工作对话。

### 任务卡片

- 打开「任务管理」：出现「纳管对话 · N」+ 卡片。
- 卡片上有标题、状态胶囊、「打开对话」、「执行汇报（Markdown）」。
- 点「打开对话」跳到那个工作对话。

### 执行汇报

- 点「执行汇报（Markdown）」：新标签页打开 Markdown 文档，含执行对话 id、状态、预设与最近几轮回报正文。
- 回报正文是人话（**本轮结束（completed）** + 摘要），不是原始 JSON。

### 提问与回复框（ADR-0012 不阻塞 + ADR-0013 只在任务卡片上）

- 让工作对话提一个必须由人决定的问题。
- **管理对话里不出现任何问答卡片**（没有「跳过 / 提交」按钮），管理端只在正文里说明问题挂在它的任务卡上。
- 任务卡片**不**变成「等待回复」，而是多一枚「等待你的答复 · N」；卡片下方出现问题原文与回复框。
- 同时 `~/.dsh/manager-questions/<管理对话 id>.md` 出现一条「待答」，提问方是**工作对话**，含问题与"已按临时方案继续"。
- 工作对话**不会停**：它自己选一个临时方案继续做，并在回复里说明这个假设。
- 在卡片回复框作答并发送：答复写回同一份 Markdown；管理对话把答复转给原工作对话，它按答复重做受影响部分。
- 管理对话被归档/删除后作答：报 409 并写明原因，不假装成功。

### 边界

- 未被管理端创建的对话不出现在卡片里。
- 管理插件未启用时：面板回落显示原来的本地任务列表，并提示「管理插件未在此实例运行」。

### 添加工作区

- 在管理对话里说「把 /home/sx/projects/MyAI/.scratch/demo 加进工作区」。
- 目录不存在时：**自动建出来**并登记；侧边栏工作区列表立刻出现它。
- 再说一次同一路径：回「已经在册」，不产生第二条。
- 写相对路径（如 tmp/x）：拒绝并提示必须写全路径。
- 在该新工作区里派活：工作对话真的落在那个目录里执行。

## 本次修复（阶段 13）

- **执行汇报永远是「暂无回报」**：原来用 `listEvents` 读管理会话，但它只回 seq/type/time 元数据，正文与 source 都在 `data` 里，筛不出任何消息。改用 `readSession(sessionId).events`。
- **汇报正文是原始 JSON 信封**：路由消息是 `{type, outcome, summary}`，文档直接贴 JSON 不好读。现在拆成「**本轮结束（completed）**」+ 摘要，拆不动就原样引用。
