# 管理模式：从发任务到执行汇报

用户视角的行为说明书。写这个模式**看见什么、做什么、出什么效果**；实现细节与接口不进本文。

## 前提

- 新对话选择「管理模式」。该对话本身**不干活**：它没有命令行、文件读写、浏览器、外部工具或技能能力，只负责把活派出去、收汇报、必要时问你。
- 任务清单在侧边栏入口打开，占据中间主区域；打开它不会离开当前对话。
- 派活必须指定一个**已存在的工作区**；工作区不够用时让管理对话添加（见「添加工作区」）。

## 添加工作区

- **操作**：在管理对话里说「把 `/home/sx/projects/foo` 加进工作区」，或者直接说「在 `/home/sx/projects/bar` 建个工作区，然后在那儿做 X」。
- **条件**：路径写全（绝对路径）。
- **效果**：
  - 目录已存在 → 直接登记；目录不存在 → **自动建出来**再登记。
  - 侧边栏工作区列表立刻多出它，之后派活可以直接选它；新增的工作区排在最前。
  - 管理对话可以在同一个回合里接着在这个新工作区派活，不用你再提一次。
- **边界**：
  - 只按你写的路径建，不猜位置；相对路径一律拒绝并说明必须写全路径。
  - 同一条目录重复添加不会加出两份，只会回「已经在册」并给出原有身份。
  - **只有管理对话能加工作区**；普通工作对话没有这个能力，也不需要。
  - 加工作区只是建目录 + 登记，不改目录里已有内容、不动权限。

## 发任务

- **操作**：在管理对话里说明要做什么、在哪个工作区做。
- **条件**：目标工作区已存在；该工作区在侧边栏可见。
- **效果**：
  - 管理对话在目标工作区新建一个**普通工作对话**（用自己的执行预设，不是管理模式的子会话），把任务要求作为第一条消息投进去。
  - 任务清单里出现一张**任务卡片**，状态「进行中」。
  - 管理对话回复你一条带**「打开对话」**入口的消息，点开就跳到那个正在干活的工作对话。
- **边界**：同一件事重复说不会建出第二个工作对话；管理对话不再等它整轮跑完才回话。

## 卡片

- **显示**：标题、状态徽章、所属工作区、最后更新时间。
- **卡片底部**：状态徽章、「打开对话」、「执行汇报（Markdown）」。
- **状态取值**：进行中 / 已完成 / 发生问题 / 已暂停。
- **边界**：卡片只反映对话的真实状态；对话被停止或归档，卡片跟着停，不会自己变成「已完成」。

## 提问与回复框

- **原则**：提问**不会卡住任何工作**，而且**只在任务卡片上出现**——管理对话不会弹问你（见 ADR-0012、ADR-0013）。谁有问题谁写下来，然后按一个临时方案继续干。
- **效果**：
  - 问题写进这份任务对应的**提问 Markdown**（`~/.dsh/manager-questions/<管理对话 id>.md`）：问题是什么、我临时怎么做的、现在的状态。
  - 卡片上出现「等待你的答复 · N」，卡片下方列出问题原文和回复框；工作**照常继续**，不会因为没人答就停住，**状态也不会因此变成"等待回复"**。
- **操作**：在回复框写下答复，发送。
- **效果**：答复写回同一份提问 Markdown；管理对话代为转给原工作对话（「第几条已答复，按此重做受影响部分」），由它自己判断重做范围，不整轮重跑。
- **边界**：不回复就一直在文档里挂着，工作按临时方案继续；答复不会自动放行任何权限操作。

## 偏好沉淀

- **条件**：你明确表达了一个长期默认（"以后都这样""记住…"）。
- **效果**：存成偏好，分全局与项目两级；下次同类问题先查适用偏好，能据此答就不再问你。
- **校正**：你说「我进行校正」，管理端按你这次的说法覆写，并告诉你改了哪一条。
- **边界**：一次性资料、临时批准、密钥、模型自己的猜测都不沉淀；记忆命中不等于授权，该走的确认照走。
- **技能**：反复出现的同类问题，沉淀成一份"这类问题怎么答"的技能，下次直接照办。
- **边界**：记忆服务不可用时要明说「未保存 / 暂时读不到偏好」，不能假装记住了。

## 执行汇报

- **条件**：工作对话本轮结束、明确完成、失败或被停止。
- **操作**：点卡片底部「执行汇报（Markdown）」。
- **效果**：打开一份 Markdown 文档，含任务内容、状态、执行对话、最近回报正文与证据路径、你的回复。
- **边界**：一轮结束**不等于**完成，卡片不会因此转「已完成」；管理端没亲自跑过测试，就只能说"工作对话报告已通过"。

## 边界与失败面

- 不是管理端创建的、你也没有交接的对话，不会被自动接管。
- 管理端离线或恢复失败时，问题留在原工作对话并显示未送达原因，不静默丢失，也不转给另一个管理对话。
- 你停止、归档或撤销某个工作对话后，迟到的汇报和答复不会让它自己复活。
