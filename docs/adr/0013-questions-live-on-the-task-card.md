# 提问只出现在任务卡片上，管理会话不直接向用户提问

2026-11-03，用户确认：要回答的问题**只在任务管理面板对应任务的位置**出现，用户在那里作答，再由管理会话代为把答复转给具体工作对话。管理会话**不应该直接向用户提问**（涉及会挂住前台的提问界面）。

## 背景

ADR-0012 把提问改成非阻塞、落 Markdown 之后，管理端仍然保留着原生提问能力：工作对话提的问题转给管理端，管理端再用原生 `ask_user_question` 转问用户，于是同一个问题在管理对话里又出现一次问答卡片，而真正的任务卡片上只剩一个计数。用户实测后指出这不合理——问题应该跟着任务走，答复也发生在任务上。

## 决定

- **管理会话的 `ask_user_question` 变成占位**：不创建原生提问、不写状态，只返回「问题在任务面板上，用户在那儿答」。
- **问题的唯一落点是任务卡片**：工作对话提问时已写入提问台账并计入该任务卡片的「等待你的答复 · N」。
- **答复路径**：用户在卡片回复框作答 → 答复作为一条人类消息进入管理会话 → 管理端用 `manager_answer` 转给具体工作对话（"代为发送"）。
- **管理端缺信息时**：让工作对话把问题提出来，而不是自己问用户。

## 影响

- `session-manager` 移除管理端的原生定时提问；随之失去「用户在管理对话里直接答原生问题」这条路径，`humanReply` 观察逻辑只对改造前遗留的待答问题有效。
- 管理端测试从「原生提问 → 用户答 → 唤醒工人」改为「管理端提问被拒 → 问题只在任务侧 → `manager_answer` 唤醒工人」。
