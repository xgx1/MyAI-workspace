# 通用后台窗口控制（基于 Agent Desktop 改造）

> [!IMPORTANT]

## 已核验的现状（2026-11-05，本机 niri 会话）

用上游 v1.2.0 发行二进制只读探测，未点击、未输入、未改任何窗口状态：

| 项目 | 结果 |
|---|---|
| `status` | 可运行，无障碍授权 `granted`，支持窗口、弹层、对话框、菜单 |
| `list-apps` | 列出 17 个应用，含 pid 与是否前台 |
| `list-windows` | 列出 Helium 两个窗口、微信窗口、Unity 编辑器、Dolphin、waybar，含标题、位置、是否聚焦 |
| 后台窗口快照 | 对未聚焦的 Unity 窗口读取无障碍树成功；读取前后 niri 聚焦窗口始终是原来的 Helium 淘宝页 |
| 结论文档 | [Linux 平台说明](<https://agent-browser.dev/desktop/platforms/linux>) |

同一次探测暴露的硬限制：

- **微信不在无障碍总线上**：报 `APP_NOT_FOUND`，进程经 `xdg-dbus-proxy` 沙箱化；上游给出可操作的排查方向（沙箱共享总线、`QT_ACCESSIBILITY=1`、Chromium 需 `--force-renderer-accessibility`）。
- **Unity 只暴露浅层树**：窗口能列出，但 `ref_count` 为 0，只有成组的空壳节点，视口内画布不可语义操作。
- **niri 只有一个 `seat0`，输入不分窗口**：虚拟指针/键盘事件全部进入主座席，指针位置与键盘焦点就是人的那一个。用它们做“后台输入”会直接动到人的鼠标和当前输入框。

## 功能目标

在不切换人的前台窗口、工作区、浏览器当前标签，不移动真实指针、不改变人的键盘输入目标的前提下，AI 能查看和操作**用户指定的任意应用窗口**。

窗口属于原来的应用，继续使用原来的账号、工程、配置与历史，不复制资料、不重开实例。

## 术语

| 术语 | 含义 |
|---|---|
| 语义操作 | 通过应用自身的无障碍接口对控件执行动作，不经过指针与坐标 |
| 原数据实时共用 | 人和 AI 操作同一份原始数据，不克隆、不同步、不换账号 |
| 后台输入 | 目标窗口收到操作，而人的前台、真实指针、键盘输入目标不变 |
| 窗口作用域输入 | 只投递给指定窗口、不经过主座席焦点的合成输入 |

## 发现与授权

| 项目 | 行为 |
|---|---|
| 操作 | 让 AI 列出窗口，选定交给当前会话的窗口 |
| 条件 | 应用在无障碍总线上，或用户已按提示启用它的无障碍支持 |
| 效果 | 显示标题、所属应用、位置、是否前台；列窗口不切换前台、不激活目标 |
| 边界 | 不在总线上的应用必须明确说明原因与开启方式，不能悄悄列不出来 |
| 现状 | 窗口列举已可用（见上表） |

## 查看窗口

| 项目 | 行为 |
|---|---|
| 操作 | 读取窗口的无障碍结构；需要时截取该窗口画面 |
| 条件 | 目标存在且允许读取 |
| 效果 | 读取不改变人的前台、不弹系统选择框、不改剪贴板 |
| 边界 | 被遮挡、在其他工作区、含菜单与弹窗时要有单独结果；不能把空壳树当成已看清内容 |
| 现状 | 无障碍结构读取已验证；**窗口截图在 niri 上尚未打通**（上游在 Wayland 走 portal 且不支持指定窗口，niri 自带截图会写剪贴板） |

## 控制

| 项目 | 行为 |
|---|---|
| 操作 | 按控件语义点击、双击、右键、输入文字、设置值、勾选、展开、选择、滚动到目标 |
| 条件 | 控件暴露对应无障碍能力 |
| 效果 | 目标应用收到动作，人的前台与真实键鼠不变 |
| 边界 | 没有语义通道的控件要明确拒绝，不能退回“先激活再点” |
| 现状 | 上游已具备该能力；本项目要在 niri 上逐项验收 |

| 项目 | 行为 |
|---|---|
| 操作 | 需要时执行像素级操作：拖拽、悬停、滚轮、鼠标左中右移动、组合键 |
| 条件 | 目标窗口是当前前台窗口，或已启用窗口作用域输入后端 |
| 效果 | 目标收到操作且不改变人的前台 |
| 边界 | 无后端时返回明确错误（`ACTION_NOT_SUPPORTED`，原因 `target_not_focused`），**绝不**改成抢焦点后操作 |
| 现状 | 未实现，依赖窗口作用域输入 |

## 原数据实时共用

| 项目 | 行为 |
|---|---|
| 操作 | AI 操作原来的窗口 |
| 效果 | 人在原应用中看到同一份生效结果，不需要导入、重登、合并 |
| 浏览器 | 用本人原有数据，不换 profile、不改本人当前标签 |
| 编辑器 | 用原工程与原资源；不为隔离而新建工程副本、重置配置或换账号 |
| 禁止 | 不热复制运行中的资料、不删应用锁、不强开冲突实例、不强退人的应用 |
| 现状 | 已被“操作既有窗口”这一路线天然满足，无需另做数据同步 |

## 多会话与人工优先

| 项目 | 行为 |
|---|---|
| 条件 | 每个会话有独立的控制上下文 |
| 效果 | 不同窗口可并行；同一窗口的写操作不交错；人接管时立即停止继续输入 |
| 边界 | 共享同一份数据意味着状态可能互相关联，遇到冲突停下提示，不覆盖人的未保存修改 |

## 失败与退出

- 应用不在总线、控件无语义通道、窗口消失、引用过期时，给出可操作的原因与下一步，不静默降级。
- 严禁失败后改用人的前台窗口或全局键鼠补救。
- 退出只回收自己的控制资源，保留原应用与未保存工作。
- 关键操作以重新读取窗口状态作为成功依据，“命令返回成功”不算。

## 验收标准

| 场景 | 通过条件 |
|---|---|
| 人持续在前台输入，AI 操作另一窗口 | 前台窗口、工作区、标签、真实指针、输入目标全程未变，不是事后恢复 |
| 浏览器（Helium）、微信、Dolphin、Unity | 能列出各自的窗口并对其可语义控件执行操作，结果在应用里可见 |
| 无语义通道的界面（Unity 视口、游戏画面） | 如实报告不可操作及原因；若启用窗口作用域输入后可用，操作同样不影响人的前台 |
| 沙箱应用（微信） | 按上游说明启用后可用；未启用时给出准确原因 |
| 多会话争用同一窗口 | 不交错、不残留按下状态、不覆盖未保存修改 |
| 退出与故障 | 只回收自身资源，不关闭或强退人的应用 |

> 本轮只做了只读探测：没有点击、没有输入、没有截图，也没有修改桌面或任何源码。全部控制能力尚未验收。

## 控制能力的两档（第二档已确认要做）

| 档位 | 覆盖 | 代价 | 决定 |
|---|---|---|---|
| 一、应用无障碍接口 | 浏览器、聊天、文件管理器、编辑器外壳等有无障碍语义的界面 | 无需动桌面 | 已在现有实现里可用，本项目适配 niri 并验收 |
| 二、窗口作用域合成输入 | 画布类界面：Unity 视口、游戏画面等没有语义通道的部分 | 需要改 niri 合成器并重启桌面 | **已确认要做（2026-11-05 用户拍板）** |

第二档的含义：给 niri 增加“按窗口投递的合成输入”通道，事件只送给指定窗口，人的座席焦点、真实指针、键盘输入目标不受影响。它不是“抢焦点后恢复”，也不是全局虚拟键鼠。

风险与门槛（计划阶段细化）：要改动并重启当前桌面，需要独立回退方式；先以最小可验证范围（单个窗口的指针移动与左键点击）打通，再扩展键盘与拖拽。
